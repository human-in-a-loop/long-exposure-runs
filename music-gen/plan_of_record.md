## Housekeeping event pattern

Codified per-cycle housekeeping ledger-event pattern (organically emerged
since cycle 3, hardened cycle 29). At the tail of every cycle, after the
named milestone events land, the worker emits two housekeeping events:

- `_archive/cycle-<N>-scratch`: records the archival of one-shot emitters
  and investigation scratch to `tools/stale/`. `artifacts` lists each
  archived file's new path under `tools/stale/`. Prevents scratch-file
  drift and preserves the ledger's audit trail of what was written.
- `_infra/adopt-cycle<N>-tests`: records adoption of that cycle's new
  test files under the ledger. `artifacts` lists each new test path.
  Clears any `promise_check` WARNs surfaced when a test file lands
  outside a milestone-adopted directory.

Both events use `status: validated`, `confidence.level: high`, nested
`confidence: {level, rationale, assessor}`, `narrative` field (not
`summary`), pinned `run_id`, UUID5 content-hash `event_id` (auto-derived
by the ledger writer). They fire AFTER `_run/cycle_<N>_closed` — the
closed-cycle event marks the cycle's substantive milestones as landed;
the housekeeping events are pure bookkeeping and do not gate any
downstream cycle.

Rationale: consolidates the ad-hoc `_archive/<name>-scratch-<cycle>` and
`_infra/adopt-fanout-artifacts-<parent>` variants that accreted across
cycles 3–28. Naming is stable, discoverable via `grep _archive/cycle-`
and `grep _infra/adopt-cycle`, and preserves the promise-check contract
(no milestone-id drift).

## Out of scope (explicit)

- Ableton Live, Pro Tools, or any DAW requiring GUI/licensing (superseded 2026-08-28).
- Per-instrument isolation inside the "other" stem in the first milestone — deferred to a refinement round.
- Any decision, model input, or curation branch that reads a non-factor attribute.

## Pointer to ledger

Every milestone status, history, and judgment lives in `promise_ledger.jsonl`,
filtered by `milestone_id`. Run `promise_check` to materialize the current
state for the human; agents call it via Bash:

    python3 -m long_exposure.tools.promise_check .

The directive section above is **immutable** after creation. Goals and
milestones tables are mutable, but every edit must emit a ledger event with
`milestone_id: "_plan/<descriptive-change-name>"` so the audit trail is
complete.
